## high: Existing databases without alembic_version are stamped as migrated without applying migrations

id: fnd_sig-feat-library-a3da278c64-e9fb_eb31f4f074
category: data-loss
confidence: high
triage: confirmed-bug
status: open
feature: Python source alembic (feat_library_a3da278c64)

evidence:
- alembic/env.py:83-101 (run_migrations_online)

The fresh-database shortcut treats absence of alembic_version as proof that the database is empty. That is not equivalent: an existing pre-Alembic or partially initialized SQLite database can contain application tables but no alembic_version table. In that case create_all() will not add missing columns to existing tables, the code stamps the database at head, and then returns before running migrations. The deployment will believe the schema is current while required migration changes are absent, causing runtime failures and potentially preventing later automatic repair because the version table says head.

recommendation:
Only use the create_all-and-stamp shortcut when the database is genuinely empty, for example when no application tables exist. If application tables exist without alembic_version, create the version table at the appropriate base revision and run idempotent migrations, or fail with an explicit recovery message instead of stamping head.

test analysis:
No linked tests are included for Alembic bootstrap behavior, and there is no evidence of a test that exercises an existing database with application tables but no alembic_version table.

suggested regression test:
Add an Alembic integration test that creates an older SQLite schema with at least one existing app table and no alembic_version table, runs the online migration path, and asserts required migrated columns/indexes exist and alembic_version is not stamped without applying migrations.

minimum fix scope:
Update the fresh-database detection in `run_migrations_online()` and add a migration/bootstrap test for the existing-unversioned database path.

repro:
Create a SQLite database with one or more existing Ghostwriter tables but no alembic_version table, with a schema older than the current SQLModel metadata. Run `alembic upgrade head`. The branch at lines 83-101 stamps the database to head and skips all migration scripts; missing columns remain missing.

id: fnd_sig-feat-library-2077975213-0afc_0226355c75
category: security
confidence: high
triage: confirmed-bug
status: open
feature: Python source app/services#2 (feat_library_2077975213)

- app/services/youtube_channel_resolver.py:69-88 (resolve_youtube_channel/_resolve_from_page)

The linked tests cover transcription and YouTube video URL extraction only; there are no reader fetch or YouTube channel resolver tests for private hosts, redirects, or non-YouTube URLs.

suggested regression test:
Add async tests that mock a public URL redirecting to localhost and assert fetch_html_document rejects it before fetching the private response; add a /youtube/resolve or resolver test that rejects http://127.0.0.1 and non-youtube.com hosts.

minimum fix scope:
app/services/reader_service.py and app/services/youtube_channel_resolver.py, with focused tests for redirect and host validation.

repro:
Serve a public HTTP URL that returns a 302 Location: http://127.0.0.1:8080/ and pass it to reader mode, or POST an internal URL to /youtube/resolve. The server attempts the internal request before returning an error or parsed result.
