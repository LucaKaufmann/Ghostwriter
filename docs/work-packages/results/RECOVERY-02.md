# RECOVERY-02 result

Implemented atomic local digest publication and durable Gmail/Wallabag acknowledgement intent on the combined backend base with Alembic 026. Migration 027 creates the source acknowledgement ledger; the model is registered for fresh databases and Alembic. The EPUB is finalized before one SQLite publication transaction writes all article rows, seen rows, checked media claims, receipt intents and completed state. A failed commit rolls back those claims, while a post-commit logging or remote error leaves the completed edition truthful. Empty editions keep the existing completed-with-zero behavior.

Provider item IDs remain paired with selected articles through filtering and summarization. The receipt stores SHA256 comparison keys for verified account/destination and action settings, without raw account, endpoint, credentials, content or provider response bodies. Gmail reads profile identity using the fetch token; on dispatch it verifies profile and marks messages with one captured token so a changed token file cannot redirect old IDs to another account between calls. Wallabag archive/tag errors remain retryable, including a non-200 tag response. Pending receipts are retried in single-process scans on later runs and startup, capped at 50 items and 30 seconds per pass. A publication overlapping an active scan queues a digest-specific bounded follow-up; the edition returns promptly, and the later pass dispatches its receipts without another external trigger. For a digest over 50 items, bounded follow-up passes continue through unattempted receipts, while failed attempts await a later run or startup. A timed-out receipt stays pending. Changed or unverifiable source identity suspends dispatch. Attempt-age ordering prevents old mismatches from starving later receipts. A receipt survives digest deletion. Provider calls are at least once because a success followed by a crash before the local `done` commit is replayed.
