# AGGREGATE-ANDROID-URL-REVERT

Acceptance base: `808548243b6a6f1c43e50f14f513b649c76bb155` on `codex/aggregate-android-url-revert`. Scope: Android Settings URL setter, Room feed-sync adapter, and focused tests. Hosted finding: PR119 `4116541274`.

Plan and result:

- [x] Trace saved URL, Room binding, generation, token, and resolution ordering.
- [x] Invalidate in-flight tokens on each real normalized configured-URL change without converting a temporary A→B→A edit into a durable server-change suspension.
- [x] Let actual destination selection suspend A when it observes B; preserve genuine instance/integrity suspension, diagnostic, and every outbox proposal.
- [x] Guard token use, outcome labels, and correction/resolution against a mismatched saved URL, including the gap between generation commit and preference publication.
- [x] Bind each persisted sync outcome to the server key, generation, configured URL, and enabled state observed when its token is acquired, so an old A result cannot overwrite status after A→B→A.
- [x] Verify disk/reopen, failed Room write, selected B, held tokens, injected publication gap, disabled local correction, and the full Android/shared/debug gate.

`SettingsRepository.setGhostwriterUrl` now serializes concurrent URL setters with a narrow Mutex. The first Room transaction increments the active binding generation when the normalized saved URL changes, leaving suspension and diagnostics untouched. The second Room transaction publishes SharedPreferences with a checked synchronous commit and updates the URL Flow immediately after the successful commit. A failed generation write leaves prefs unchanged; a crash between the two stages can leave only a harmless generation increment. The second Room boundary prevents an adapter transaction from straddling preference publication, while adapter transactions can run in the safe gap before it. No schema or shadow state was added.

`AndroidFeedV2Store.currentDestination` reads the saved URL inside its Room transaction. If a sync actually selects B, it suspends the old A binding and keeps the old scope available for explicit Review; returning to A never clears that suspension automatically. `beginSyncRun` validates Room and prefs, then assigns its token synchronously after the transaction returns so cancellation cannot leak Busy. A suspended binding remains readable to let the shared use case report `ServerChanged` without a remote request. Every token mutation rejects suspension, generation mismatch, or configured-URL mismatch. `resolve` and `correctRejected` require the saved URL to match the active binding but remain usable with Ghostwriter disabled for local-only review.

All production sync callers use `syncAndRecord`. A coroutine-local capture receives an immutable Room/settings ticket when `beginSyncRun` actually acquires its token; no preparatory destination selection is needed. Outcome persistence requires that server key, generation, configured URL, enabled state, and unsuspended binding still match. A `NotConfigured` result uses only the disabled observation made when `currentDestination` returned null. Busy or failed admission has no outcome ticket. The initial configured bind records success, a held A result after B→A cannot replace current status, and a valid token acquired after that roundtrip can record success. Cancellation still propagates; the worker's returned outcome and retry choice are unchanged.

Focused six-test Robolectric suite passed against a real disk-backed Room database and synthetic secure-preference fixture. It covers A→B→A before selection with a held old token, a preserved outbox after reopen, actual B selection yielding `ServerChanged` without remote calls, genuine changed-instance suspension and diagnostic surviving a URL roundtrip, blocked correction while B is configured with local correction still available when disabled on A, and a forced Room generation-write failure leaving the old URL and proposal intact. A separate fixture injects preference publication after a token starts at the new generation, proving the configured-URL guard blocks writes independently of generation. No paid or live provider was called.
