# Native delivery implementation handoff

Prepared 2026-09-27 against accepted shared prerequisite `99fcda5` and contract PR82. This is a source-validated dispatch supplement, not implementation evidence. Dispatch only after the platform's sync/delete owner freezes its accepted Room9 or SwiftDataV2 revision. Root supplies that exact base; migration numbers remain Room10 and SwiftDataV3. The full behavior and fixture matrix in `docs/contracts/feed-sync-and-local-delivery.md` remains authoritative.

## Common acceptance

Use the accepted shared `ArticleDeliveryIdentity` helper (PR100), including its raw URL semantics and platform SHA256. Feed identity remains the exact stored URL. Normal runs parse the available feed page, deduplicate normalized links per feed, exclude delivered and same-signature excluded rows, order eligible identities by persisted least-recent attempt sequence with source-order ties, then apply the cap (`0` unlimited). Publication date cannot exclude candidates. Persist attempt markers before processing; retryable rows remain eligible after failure or cancellation. Invalid identities are reported without a title/date fallback.

A platform-wide generation gate must cover every local manual, scheduled and retry entry point, including separately constructed generator/service instances. It prevents duplicate paid work; a second independent safeguard atomically claims normal delivery in the same transaction as completed history and associations. An already-delivered claim rolls back the entire losing history/ledger transaction and removes only its unique artifact. Existing retryable or newly eligible excluded rows are valid transitions. Explicit regeneration remains serialized, may repeat delivered articles and must not erase or rewrite an earlier delivery claim.

A completed artifact must be durable before finalization. Failure/cancellation before the database commit leaves all selected identities undelivered; failure after commit cannot demote the completed digest or erase its ledger. Persist diagnostics in `GenerationRun` even for empty/deferred/failed runs without a downloadable digest. Keep delivery rows after history deletion and feed deletion/re-add; no cascade or reset on server reconfiguration. Filtered identities commit only at the accepted completed-result boundary and carry a signature of filter revision/preferences. A changed signature or explicit regeneration re-evaluates exclusions; neither changes delivered identities.

Use structured feed results and persisted run outcomes from the contract: mixed usable output is partial; all failures are failed; successfully parsed absence of eligible items is empty; filtered-only selection with cap overflow is deferred. Failed feeds cannot erase usable siblings. Cancellation propagates. UI should show useful counts/reasons without source bodies or credentials. Fixtures use mocks for extraction/AI and temporary real databases/artifacts.

## Android owner

Take sequential ownership of `ArticleRepository`, `DailyDigestWorker`, `DigestRepository`, `DigestDao`, `DigestArticleEntity`, database/DI wiring, delivery/run entities and DAOs, and scoped tests after sync relinquishes them. Add nullable association `feedUrl` and reserve Room9→10. Do not infer historical source identity from `feedName`: old Android associations lack feed URL, so only provable identities may be backfilled; disclose that a historical article can appear once after upgrade. Preserve unique-artifact/reference-aware deletion and WorkManager observation changes already accepted.

`RssService.fetchFeed` currently catches every exception and returns an empty list; `fetchNewArticles` applies `lastFetched`. A typed/new throwing fetch seam is required for generation, with cancellation preserved; retain unrelated feed validation behavior. `ContentProcessor` and `OpenAIService` likewise need typed distinctions where null currently conflates filtering and failure. Android transient summary failure retains its full-article fallback, reported as such. Model-declared promotional content must be excluded, not included by fallback. Root prepared this typed seam in `codex/android-filter-outcomes` commit `7e5efb2`, but independent review showed it cannot be accepted alone: capped filtered-only batches starve later items and repeat provider work without durable exclusions. Incorporate that code into Room10 delivery, implement the attempt/exclusion semantics together, then review the combined behavior. The evidence-only follow-up is `a32ce83`; neither commit is an accepted implementation or published PR.

`DailyDigestWorker.KEY_FETCH_ALL` becomes explicit regeneration only. `SettingsViewModel` currently invokes `runNow(fetchAll=false)` and `DigestScheduler.runNow` passes the flag; give the user a clearly labeled regeneration action instead of changing normal manual behavior. Include scheduler/manual ownership only after the sync owner releases SettingsViewModel. Ordinary workers remain local-only when Ghostwriter is configured. Optional custom-directory export stays best effort and must not invalidate an otherwise durable local digest.

Required checks include actual Room9→10 and frozen Room8→9→10 upgrades, fresh/reopened database, atomic history/ledger rollback and state-aware claim conflicts, cancelled/restarted runs, two generator entry points, history cleanup preserving ledger, max2 of5 across runs, permanently failing first candidates with fair later progress, no-date/late-date/duplicate URLs, extraction/AI/filter cases and explicit regeneration. Run focused behavioral tests, Android/shared suites and debug build; inspect relevant UI if available.

## iOS owner

Append V3 and delivery/run models to the accepted capturedV1→V2 plan; preserve exact previous schema classes. Own Data article/digest repositories and generator, Domain protocols/models, LocalDigestService, LocalDigestScheduler construction/gate, explicit regeneration entry point and scoped tests. Register the shared identity dependency only through source Tuist manifests if needed; never edit generated projects. Actual legacy `DigestArticle` has feedUrl/originalUrl, so backfill valid identities only for completed local (`remoteId == nil`) digests, preserving all remote/failed/ambiguous history. Test actual unversioned→V1→V2→V3 as well as V2→V3/reopen.

`ArticleRepository` currently caps before dedup and suppresses per-item errors with `try?`; `DigestGenerator` suppresses entire feed failures the same way. Replace both with structured results while retaining iOS's retryable briefing AI error behavior. Intentional `contentTooShort` is distinct from extraction/provider errors. Feed task completion order must not silently reorder source candidates before fair selection. Capture sendable value snapshots before concurrent work rather than passing live SwiftData models across actor boundaries.

Native linking constraint validated during feed sync: the static EpilogueShared XCFramework must remain linked by one image (`GhostwriterClient`). Linking it again directly into App or a hosted XCTest bundle produced runtime failures. Reuse the shared identity helper through a small Swift value-only wrapper exposed by that existing framework owner; do not independently port URL normalization or add duplicate static framework links. Any necessary Tuist dependencies must stay acyclic and source-defined. Migration backfill needs the same helper before the store opens; avoid a late optional global registration hook that could silently skip backfill. Freeze the exact accepted V2 schema/legacy fixtures before any V3 changes to model types.

`LocalDigestService` currently has an instance-local `isGenerating`, while `LocalDigestScheduler` has a separate gate and builds its own generator. Both must use the same coordinator; a generator finalization transaction must still reject duplicate claims across independent instances. Disable unsafe autosave during semantic finalization, save history/associations/ledger/run together and roll back the context on failure. A failed post-commit notification/export cannot turn a completed digest into a failed one.

Required checks mirror Android with actual SwiftData saves/reopen, provable local-history backfill, rollback injection, two independent contexts/generators and cancellation. Build the shared XCFramework and regenerate through Tuist, then run affected Domain/Data/App tests and simulator build. Inspect normal/partial/empty/deferred and explicit regeneration UI. Later IOS-RECOVERY should build on GenerationRun identity to distinguish abandoned local runs from active work and remote jobs; do not invent a second incompatible job journal here.

## Handoff to later packages

IOS-SYNC-STATUS follows the sync owner on coordinator/config/digest/schedule apply results. Feed outcomes becoming truthful in the sync PR does not prove non-feed combined ingestion; normal/forced/fallback failures need separate tests. IOS-RECOVERY follows delivery on generator/service/scheduler and must handle cold-start abandoned pending rows without duplicating active local work or touching remote jobs. ANDROID-FILTER acceptance is combined with delivery's fair-attempt/exclusion ledger and must preserve transient fallback and cancellation; its prepared local code remains held until then. Root integrates each accepted stage and records exact verification; these notes do not claim those packages completed.

Recovery coverage clarification (2026-09-27): a settled successful empty or deferred scheduled run covers its current scheduled period until the next window. Deferred candidates remain eligible for a subsequent manual edition or next scheduled edition; foregrounding alone must not loop generation/paid work. Active in-process runs suppress duplicates; stale pending local runs must not cover forever, and remote jobs are never classified as abandoned local work. IOS-RECOVERY implements this after the delivery journal is verified.


IOS-RECOVERY implementation refinement (2026-09-27, after delivery runtime proof): reuse the process-wide generation gate with an exclusive recovery/admission lease; no second journal or schema change. Under that lease, reconcile persisted running local GenerationRun rows, preserving any committed usable digest and claims; otherwise mark interrupted/failed with a safe diagnostic and retained retryable attempts. Resolve legacy local pending Digest rows as interrupted, never remote jobs. Admission, period attempt counting and run start must share the gate so concurrent scheduler callbacks cannot exceed the budget. Allow at most two automatic attempts per scheduled occurrence (initial plus one recovery retry), counting legacy scheduled pending/failed history where provable. Completed/partial/empty/deferred cover that occurrence. Explicit manual work and the next scheduled window remain eligible. Preserve existing successful manual/nil-period legacy coverage rules. Inject clock/calendar and exercise reopen, second restart, active run, postcommit preservation, empty/deferred, cancellation, remote jobs, manual override and next window.
